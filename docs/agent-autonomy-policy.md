# 에이전트 자율 실행·추론 기록 정책

프로젝트 운영자가 **실질적 개입이 필요한 순간**이 오기 전까지는, 에이전트가 멈추지 않고 구현을 진행할 수 있도록 하는 **기본 합의**다. 다른 저장소로 복사해 두고 동일 규칙을 쓸 수 있다.

원천 요구: 이 저장소에서는 **[PRD.md](PRD.md)**, **[web-project-common.md](web-project-common.md)** 가 우선한다.

---

## 1. 기본 원칙

1. **기본은 실행**  
   사용자가 개발을 요청했을 때, **반드시 사용자 결정이 필요하지 않은 사항**은 에이전트가 PRD·공통 가이드·코드베이스 관행에 맞춰 **스스로 추론해 구현**한다.

2. **추론은 문서로 남긴다**  
   구현 과정에서 사용자에게 묻지 않고 정한 선택(가정·트레이드오프·대안 포기 이유)은 **[inferred-decisions-log.md](inferred-decisions-log.md)** 에 **작업 단위로** 적는다.  
   대화 말미에는 그 로그의 **해당 절**을 짧게 안내한다.

3. **질문은 예외**  
   아래 §2에 해당할 때만 사용자 확인을 요청한다.

---

## 2. 사용자 확인을 요청해야 하는 경우

- **파괴적·되돌리기 어려운 조치**: 프로덕션 DB 초기화, 대량 데이터 삭제, 이력 말소 등
- **보안·규제·비밀**: 자격 증명을 저장소에 넣는 방식, 개인정보 처리 방식을 PRD/법무와 어긋날 수 있는 변경
- **원천 요구와 충돌**: PRD와 다른 제품 결정이 필요해 보일 때(충돌 내용·대안을 로그에 적고 질문)
- **외부 비용·계약**: 유료 API·새 구독이 필요한 아키텍처
- **환경 의존으로 검증 불가**: 필수 시크릿·로컬 DB 없이 “완료”를 주장할 수 없을 때 — 무엇이 막혔는지 로그에 적는다

---

## 3. 추론 시 우선순위

1. **PRD** 및 명시된 체크리스트
2. **web-project-common.md** (환경 변수, 인증 분리, 테스트 관행 등)
3. **기존 코드 스타일·디렉터리 구조**
4. 업계 일반 관행(이 충돌하면 1–3에 맞춘다)

---

## 4. 테스트·검증

- 저장소에 정의된 테스트·린트·타입체크가 있으면 **변경 후 실행**을 시도한다.
- 실행 불가 시(도구 없음, 환경 없음): 로그에 **건너뛴 이유**를 적는다.

---

## 5. 로그 작성 형식 (요약)

`inferred-decisions-log.md` 에는 역순(최신이 위)으로 아래를 **한 덩어리**로 추가한다.

- **날짜**(및 필요 시 짧은 제목)
- **맥락**: 무슨 요청에 대한 응답인지 한 줄
- **추론한 결정**: 불릿으로 (무엇을, 왜)
- **대안**: 버린 선택이 있으면 한 줄
- **검증**: 실행한 명령·결과 요약(또는 미실행 사유)

---

_이 정책은 운영자가 변경하기 전까지 에이전트 세션의 기본 행동 기준으로 삼는다._
