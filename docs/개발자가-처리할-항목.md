# 개발자가 처리할 항목 (학원 관리 프로젝트)

운영 원칙·형식은 **[web-project-common.md §6](web-project-common.md#6-외부-등록비밀-작업체크리스트-운영)** 과 동일하게 유지한다.  
아래는 **본 저장소(학원 관리)** 에 특화된 체크 항목이다.

애플리케이션 코드와 별도로, **개발자(또는 DevOps)가 외부 콘솔·계약·키 발급을 직접 수행해야 하는 작업**을 정리한다.  
**적정 단계**(예: OAuth 연동 착수 전, 입금 자동화 스프린트 착수 전, 프로덕션 배포 전)에 도달할 때마다 이 문서를 열어 해당 섹션을 **체크**하고, 완료 일자·담당자를 기록한다.

> 저장소에 비밀번호·클라이언트 시크릿·실키를 커밋하지 않는다. 확보한 값은 `.env`(비커밋) 또는 배포 Secrets에만 넣는다.

---

## 체크리스트 사용법

- [ ] 미완료 / [x] 완료
- 각 항목 완료 시 **완료일**, **비고**(예: 앱 ID 마스킹된 식별자)만 기록.

---

## 1. OAuth 소셜 로그인 (Better Auth 연동 전제)

**언제:** 소셜 로그인·회원가입 플로 구현을 시작하기 전.

- [ ] **카카오** 개발자 콘솔: 앱 등록, Redirect URI 등록(로컬·스테이징·프로덕션), 동의 항목 설정, REST API 키·Client Secret 확보
- [ ] **네이버** 개발자 센터: 애플리케이션 등록, Callback URL, Client ID·Secret
- [ ] **구글** Cloud Console: OAuth 동의 화면 구성, 클라이언트 ID·Secret(Web), 승인된 리디렉션 URI
- [ ] 각 제공자 **검수/앱 공개 상태** 요건 확인(프로덕션 트래픽 전)
- [ ] `.env`에 필요한 키 이름을 `.env.example`에 주석과 함께 반영(값은 넣지 않음)

---

## 2. Better Auth·배포 환경

**언제:** 실세션 로그인을 스테이징/프로덕션에 올리기 전.

- [ ] `BETTER_AUTH_SECRET` 등 시크릿 생성·Secrets 저장소 등록
- [ ] 프로덕션 **공개 URL**(`PUBLIC_APP_URL` 등) 확정 및 OAuth Redirect URI와 일치 확인
- [ ] **가장 로그인(`AUTH_IMPERSONATE_*`) 프로덕션 비활성** 검증

---

## 3. 입금 자동화 — 은행(오픈뱅킹 등) API

**언제:** `billingAutoImport`·자동 매칭 스프린트 착수 전.

- [ ] 이용 예정 **금융기관·중계 표준**(예: 금융결제원 오픈뱅킹, 특정 은행 개발자 포털) 확정
- [ ] **사업자·약정·테스트앱** 신청 및 승인 일정 파악
- [ ] 샌드박스(있는 경우) 키·클라이언트 정보 확보
- [ ] 운영 키 발급 후 `.env` / Secrets 반영, `.env.example` 주석 갱신
- [ ] 개인정보·금융 관련 **약관·동의** 요건이 제품에 반영되었는지 검토(법무 협의)

---

## 4. MongoDB·인프라

**언제:** 공유 개발·스테이징 환경 구축 시.

- [ ] Atlas(또는 자체 호스트) 클러스터·네트워크 접근(IP 허용/VPC)·백업 정책
- [ ] `DB_URL` 연결 문자열을 Secrets로 분배

## 5. E2E(Playwright) 실계정

**언제:** MVP 완료 후 실사용자 플로 자동화 전.

- [ ] 테스트 전용 계정을 담당자에게 요청해 생성
- [ ] 자격 증명을 GitHub Actions Secrets(또는 동등)에만 저장
- [ ] 저장소·로그에 비밀 노출 없음 확인
